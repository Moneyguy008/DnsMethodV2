Troubleshooting & common problems

Click any problem to expand the fix. Most issues come down to one of two things: a VPN app getting in the way, or a network that blocks plain DNS.

🩺 Run the diagnostic first

Not sure what’s wrong? This script checks everything at once — whether plain DNS is blocked, whether encrypted DNS gets through, and whether a site is blocked by DNS or by IP. It’s safe and read-only (it just resets your DNS to automatic so you keep a connection while testing).

⬇︎ Download dns-diagnostic.sh

Run it on the problem network:

zsh ~/Downloads/dns-diagnostic.sh

Common problems

“Profile installation failed — the ‘VPN Service’ payload could not be created”

Cause: You have a VPN app (like ExpressVPN, NordVPN, etc.) installed. macOS lets only one “VPN service” exist, and the DNS profile needs that slot. Even when the VPN is disconnected, its background service keeps the slot reserved.

Fix: Skip the profile and use Method 2 (dnscrypt-proxy) instead — it doesn’t create a VPN service, so it works alongside any VPN. If you don’t need the VPN app at all, fully quitting/uninstalling it will also let the profile install.

The downloaded profile shows a red “Error”

Cause: The file didn’t download correctly (often it’s a tiny “404 Not Found” page instead of the real profile).

Fix: Select the errored profile in System Settings → General → VPN & Device Management and remove it with –. Then re-download the profile and open it again. You can confirm a good download in Terminal:

plutil -lint ~/Downloads/Private-DNS-Cloudflare.mobileconfig

It should say OK. If it says the file is tiny or invalid, the download failed.

I changed my DNS and now I have ZERO network / nothing loads

This is the most common one. There are three usual causes:

1. You set a plain DNS like 8.8.8.8 or 9.9.9.9 on a network that blocks port 53. Many restrictive networks block outside DNS, so your Mac can’t reach that server and every lookup fails. Fix: use encrypted DNS (the whole point of this guide) instead of a plain DNS IP. To recover right now, reset DNS to automatic:

networksetup -setdnsservers "Wi-Fi" "Empty"

2. Your local resolver isn’t actually running (Method 2). If your DNS points at 127.0.0.1 but nothing is listening there, everything breaks. Check it:

sudo brew services list | grep dnscrypt
dig @127.0.0.1 example.com +short

If the second command returns nothing, start the service: sudo brew services start dnscrypt-proxy

3. You set DNS on the wrong network interface. If you’re on Ethernet/a dock but set DNS on “Wi-Fi” (or vice-versa), it won’t take effect. Find your active interface and its service name:

route -n get default | grep interface
networksetup -listallnetworkservices

Then set DNS on the service you’re actually using.

How do I know if a site is blocked by DNS (fixable) or by IP (needs a VPN)?

This decides whether this guide can help at all.

  • DNS block (fixable here): the network’s DNS gives a fake/“block-page” address for the site. Encrypted DNS returns the real address and the site loads.
  • IP / firewall block (NOT fixable with DNS): even with the correct address, the network refuses the connection to the site’s servers. Only a VPN can bypass this.

Quick test: if the site loads on a VPN but not otherwise, and normal websites still work — it’s very likely a DNS block, and this guide will fix it. For a definitive answer, run the diagnostic script above — it literally tells you “DNS fix will work” or “needs a VPN” for the site you test.

“brew: Could not resolve host” when installing

Cause: Your DNS is currently broken (e.g. still set to a blocked plain DNS), so Homebrew can’t download anything.

Fix: Reset DNS to automatic first so you have a working connection, then install:

networksetup -setdnsservers "Wi-Fi" "Empty"
brew install dnscrypt-proxy
It works on one network but breaks on another

Cause: Some strict networks block the well-known DNS IP 1.1.1.1 specifically. Our advanced config already includes CDN-IP fallbacks (Cloudflare addresses shared with normal websites) that are almost impossible to block. If you set it up manually, make sure your config’s server_names includes 'cf-cdn' (see the manual steps).

If encrypted DNS itself is fully blocked (rare), no DNS method will work on that network and you’ll need a VPN.

Is this a VPN? Will it slow me down?

No, and no. It only encrypts the tiny DNS lookups (“what’s the address for this name?”), not your actual traffic. Your connection speed is unchanged. It also doesn’t hide your browsing the way a VPN does — it just stops the network from tampering with or spying on your DNS.

Does a VPN override this? Can I run both?

Yes, they coexist. When a VPN is connected, it uses its own DNS (that’s normal). When it’s off, you’re back on this encrypted-DNS setup. The dnscrypt-proxy method causes no conflict because it isn’t a “VPN service.”

How do I completely turn it off / undo everything?

Profile method: System Settings → General → VPN & Device Management → select the profile → – (remove).

dnscrypt-proxy method:

sudo brew services stop dnscrypt-proxy
networksetup -setdnsservers "Wi-Fi" "Empty"
brew uninstall dnscrypt-proxy

Or run the uninstall script.

How can I verify it’s actually using encrypted DNS?

Plain DNS to an outside server should fail on a locked-down network, while your normal lookups succeed — that gap means your lookups are going out encrypted, not on port 53:

dig example.com +short          # should work (via your encrypted resolver)
dig @8.8.8.8 example.com +short  # may time out on a network that blocks port 53

You can also confirm the resolver is answering locally: dig @127.0.0.1 example.com +short

Still stuck? Re-run the diagnostic and compare against these cases — the combination of “port 53 blocked / DoH works / real IP reachable” tells you exactly which fix applies.
