Set up private DNS on Mac and fix “DNS won’t resolve” errors

A simple, step-by-step guide to switching your Mac to encrypted DNS (DNS-over-HTTPS). It works even on networks that block normal DNS, and it doesn’t slow your connection down like a VPN.

🔎 Will this actually help me?

This fixes DNS-based problems — when a network blocks or hijacks DNS, or your custom DNS won’t connect. It cannot fix a site blocked at the firewall/IP level (that needs a VPN). Quick test: if a site loads on a VPN but not otherwise, and normal websites still work, this will probably fix it. See DNS block vs IP block.

What is this, in plain English?

Every time you open a website, your Mac asks a DNS server “what’s the address for this name?” Normally that question is sent unencrypted on port 53, so the network can see it, block it, or lie about the answer (for example, pointing a blocked site at a “blocked” page).

Encrypted DNS (DNS-over-HTTPS / DNS-over-TLS) sends that same question encrypted over port 443 — the same port normal websites use. The network can’t read it, block it, or tamper with it. Because it only encrypts the tiny lookups (not your whole connection), there’s no VPN-style slowdown.

⚠️ Please use this responsibly

Only change DNS on a network where you’re allowed to — like your home Wi-Fi or your own phone hotspot. On a school or workplace network, changing DNS may violate their acceptable-use policy. That’s your call to make.
