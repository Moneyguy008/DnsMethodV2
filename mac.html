macOS

Set up encrypted DNS on Mac

Two ways to do it. Try Method 1 first — it takes 30 seconds. Only use Method 2 if Method 1 fails (usually because a VPN app is in the way).

Which method?

Method 1 (Profile): easiest, no Terminal. Method 2 (dnscrypt-proxy): for Macs where the profile won’t install — for example if you have ExpressVPN or another VPN whose “VPN service” blocks it.

Method 1 — Install a DNS profile (easy)

  1. Download the profile

    This is a small Apple configuration file that switches your Mac to Cloudflare’s encrypted DNS.

    ⬇︎ Download Private-DNS-Cloudflare.mobileconfig

  2. Open it

    Double-click the downloaded file. macOS will say the profile was downloaded and needs review — that’s normal, it never auto-installs profiles.

  3. Install it in System Settings

    Go to System Settings → General → VPN & Device Management (older macOS: Profiles). Click “Private DNS (Cloudflare DoH)” under Downloaded, then Install and enter your Mac password.

    It will show “Not Verified.” That’s expected for a self-made profile — it just means Apple didn’t sign it, not that anything is wrong. You can open the file in TextEdit to see exactly what it does.

  4. Test it

    Open a site that wasn’t loading before. To double-check in Terminal:

    dig example.com +short

    If it returns an IP address, encrypted DNS is working. 🎉

To remove later: System Settings → General → VPN & Device Management → select the profile → – (remove).

Profile install failed?

If you see “The ‘VPN Service’ payload could not be installed” or a red Error, a VPN app is blocking it. Use Method 2 below. More detail on the Troubleshooting page.

Method 2 — Local resolver with dnscrypt-proxy (advanced)

This installs a tiny local program that answers DNS on your Mac and forwards every lookup encrypted over port 443. It doesn’t create a “VPN service,” so it works even when Method 1 is blocked.

Requirements

Homebrew (the Mac package manager). If you don’t have it, install it first from brew.sh.

Option A — Automatic script (recommended)

  1. Download the setup files

    ⬇︎ setup-dnscrypt-mac.sh

    ⬇︎ setup-dnscrypt-mac-UNINSTALL.sh (to undo later)

  2. Run it

    Open Terminal, then run (adjust the path if the file is in Downloads):

    zsh ~/Downloads/setup-dnscrypt-mac.sh

    Enter your password when asked. The script installs dnscrypt-proxy, configures it (with Cloudflare + CDN fallbacks), starts it, and points your network at it.

  3. Test

    dig example.com +short

    An IP means it’s working. To undo everything later: zsh ~/Downloads/setup-dnscrypt-mac-UNINSTALL.sh

Option B — Manual steps (if you prefer to see each command)

  1. Install dnscrypt-proxy

    brew install dnscrypt-proxy

  2. Write the config

    Open the config file:

    open -e $(brew --prefix)/etc/dnscrypt-proxy.toml

    Replace its contents with:

    listen_addresses = ['127.0.0.1:53']
doh_servers = true
dnscrypt_servers = false
ipv6_servers = false
require_dnssec = false
require_nolog = false
require_nofilter = false
server_names = ['cf-1111', 'cf-cdn']
netprobe_timeout = 0
netprobe_address = '1.1.1.1:443'
bootstrap_resolvers = ['1.1.1.1:443']
ignore_system_dns = true
cache = true

[static]
  [static.'cf-1111']
  stamp = 'sdns://AgcAAAAAAAAABzEuMS4xLjEAEmRucy5jbG91ZGZsYXJlLmNvbQovZG5zLXF1ZXJ5'
  [static.'cf-cdn']
  stamp = 'sdns://AgAAAAAAAAAADjEwNC4xNi4yNDkuMjQ5ABJjbG91ZGZsYXJlLWRucy5jb20KL2Rucy1xdWVyeQ'

  3. Start the service (needs your password)

    sudo brew services start dnscrypt-proxy

  4. Point your Mac at it

    For Wi-Fi (use your actual service name if different — check with networksetup -listallnetworkservices):

    networksetup -setdnsservers "Wi-Fi" 127.0.0.1

  5. Verify

    dig @127.0.0.1 example.com +short

    An IP address = success.

Important: they’re a pair

If you ever stop the resolver, also reset your DNS, or lookups will break (nothing would be listening). To turn everything off:

sudo brew services stop dnscrypt-proxy && networksetup -setdnsservers "Wi-Fi" "Empty"

To turn back on:

sudo brew services start dnscrypt-proxy && networksetup -setdnsservers "Wi-Fi" 127.0.0.1

Trouble? See Troubleshooting — it covers “0 network after changing DNS,” profile errors, and how to tell a DNS block from an IP block.
